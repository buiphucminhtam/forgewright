# Initialization and Session Lifecycle Reference

This entrypoint consumes `skills/forgewright/SKILL.md`, the kernel effort class,
and `skills/_shared/protocols/session-lifecycle.md`. It does not define another
bootstrap, memory or approval policy.

## Project Entry

1. Resolve the requested outcome and classify effort before expanding setup.
   Pure conversation, read-only inspection and routine QUICK work need only
   relevant context. A new repository does not automatically require Full Build.
2. For substantive repository work, use the entry skill's cheap bootstrap
   preflight when its existing launcher is available. Reuse a ready setup.
3. The trusted native hook owns automatic bootstrap mutation. Missing/disabled
   hook trust or optional tooling is not permission to run setup directly,
   install packages, reindex, edit global MCP configuration, or restart clients.
   Continue plugin-only when safe; explicit setup requests are a separate scope.
4. Check dependencies only for the capability actually needed. Derive supported
   versions from current manifests/runtime probes, not stale power-level tables.
   Missing memory or code intelligence does not prevent a source-only review.
5. Reuse existing user settings. Do not require a power-level interview or write
   default settings/production directories merely to start a prompt. Resolve
   routine reversible choices autonomously; ask only for material unknowns.

## Updates

Do not fetch/install updates on every request. An update check is relevant when
explicitly requested or when a demonstrated compatibility issue needs it. Keep
managed plugin caches and immutable hook generations under their supported
installer/update ownership; do not copy arbitrary workspace changes over them.

An actual update does not automatically end the user's task. Continue with the
verified compatible route when possible. If the host demonstrably requires a
restart, preserve task state and explain that exact boundary; do not tell the
user to re-invoke merely because an old reference prescribed it.

Workspace canonical protocols govern work in that workspace. A bundled older
reference cannot override its kernel, authorization, optional-memory policy or
exact-turn evidence requirement. Local source verification does not claim that
a separate installed plugin/global hook generation has adopted those sources.

## Session and Prompt Entry

Apply the canonical session lifecycle proportionately:

- Inspect current task/relay ownership and matching receipts; keep independent
  Web and Codex inference routes separate.
- Resume already-authorized unfinished work without a generic confirmation.
  Treat a new message as steering unless the user replaces or cancels the task.
- Refresh only material stale facts. Do not run full onboarding because a
  profile is old/missing, or inherit a stale pipeline phase as a blocker.
- Memory retrieval is optional, scoped, bounded and read-only. Respect disable
  flags and host opt-in. Empty results never trigger seeding or installation.
- Record real native turn identity from the prompt hook for exact-turn evidence.
  A thread/session identifier is not the native turn identifier.
- Label token/resource estimates as estimates. Save useful checkpoints and
  continue through compaction; only observed constraints can prevent execution.

## Specialist and Review Handoffs

Prepare a bounded handoff only when an independent specialist is needed. Reuse
existing verified context; do not create every legacy context file at startup.
The packet contains objective, acceptance, scope/forbidden paths, current facts,
material risks, runtime capability and test/evidence references. Private reasoning
is not part of the handoff. Derived caches never outrank current user intent or
workspace/runtime evidence.

Use the active host's observed tools and capability schema. Do not assume a
fixed Cursor agent list, model name, parallel-search count or token saving.
Small coupled tasks stay with the parent. Read-only reviewers report findings
and evidence without implementation-phase, Docs Hub or memory-write rituals.

## Completion

Follow the canonical lifecycle Session End sequence: observed checks/review,
honest final task state, unchanged final verifier binding that tree, and exact
receipt links. An unverified bounded Stop exit is not successful completion.
Optional memory failure, absent telemetry or an unrelated stale log cannot turn
a completed product task into a new execution blocker. Preserve actual safety,
ownership, evidence and irreversible-action gates.
